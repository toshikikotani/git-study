# 要求仕様書:個人資産形成システム(仮称)

- 版:v0.1(ドラフト)
- 作成日:2026-09-08
- 対象:本人専用(シングルユーザー)
- 用途:本書は、上位モデル(Fable等)による詳細設計・DBスキーマ生成、およびClaude Code等による実装の入力として使用する

---

## 1. 背景と目的

### 1.1 背景
- 本人は給与収入のみ(額面月収約31万円)で、高金利負債(リボ・消費者金融、年利15%台後半以上と推定)を約100万円抱えている
- 本来は几帳面で整理・リファクタリングを好む性質だが、金銭面には「整理対象としての構造」が存在せず、結果として浪費に流れている
- 投資経験があり、リスク許容度は高い。負債返済と並行して一定額の投資継続を希望している
- 「女遊び」への支出は本人の優先事項であり、削減対象とせず予算として明示的に確保する

### 1.2 目的
1. 負債を約1年で完済し、純資産をプラスに転じさせる
2. 本業・副業による収入増加の行動を継続させる
3. 完済後、月10万円以上を投資に回せる状態を作り、5年で純資産1,000万円前後を目指す
4. 上記を「意志力」ではなく「構造」によって継続可能にする

### 1.3 本システムの位置づけ
- 家計簿アプリではなく「個人財務のリファクタリング環境」
- 本人が自らスキーマ・ルール・分類を整えたくなる設計を最優先とする
- 専門家に発注すれば高額になる仕組みを、自分専用・低コストで保有する

## 2. 利用者プロファイル(設計前提)

| 項目 | 内容 |
|---|---|
| 収入 | 給与のみ、額面月収約31万円(手取り約25万円想定) |
| 負債 | 約100万円(高金利、詳細未把握。件数・金利・残高の正確な把握が未了) |
| 性格 | 几帳面・整理好き。ただし構造がないと欲に流れやすい。三日坊主リスクあり |
| 投資 | 経験あり、高リスク許容 |
| 技術 | 自分でコードを書けるが、実装はAI駆動開発を主とする |
| 可処分時間 | 副業・自己投資に週5〜10時間 |
| 聖域支出 | 女遊び(固定予算として確保、削減対象外) |

## 3. 設計原則

1. **構造を見せる**:負債・口座・ルール・カテゴリをすべてスキーマとして明示し、本人が手を入れて整えられる
2. **記録の手間を最小化**:手入力は例外。明細は自動取り込みを前提とする
3. **叱らず見せる**:説教ではなく、数字(完済まで残り日数・使える残額)を毎日見せ続ける
4. **判断は事前ルールで行う**:給料日の振替、投資額、予算上限はルールとして定義し、当日の意思決定を不要にする
5. **欲を敵にしない**:聖域支出は「残りいくら使えるか」として肯定的に表示する
6. **拡張・改修しやすい**:ロックインを避け、本人が後から自由に改修できる構成にする

## 4. ロードマップ(システムが支援する行動計画)

### 4.1 短期(〜半年)
- 負債の全容把握(借入先・残高・金利・返済日)
- 借り換え(おまとめ)の検討・実行
- 給料日自動振替ルールの確立(返済 → 投資 → 女遊び枠 → 生活費)
- 月8〜10万円の返済 + 返済額の2〜3割程度の投資を並走
- リボ・キャッシングの再発防止(該当カードの停止・解約)
- 副業(AI駆動開発による小規模受託等)の初回入金、目標月3〜5万円。副業収入は返済へ上乗せ

### 4.2 中期(半年〜3年)
- 負債完済(目標:12〜14ヶ月以内)
- 本業の転職・昇給による月+5〜10万円
- 副業の定型化・自動化による月5〜10万円の安定化
- 生活防衛資金(手取り3ヶ月分)の確保
- 完済後に高リスク投資枠を解禁(投資全体の2〜3割程度)

### 4.3 長期(3〜5年〜)
- 月10〜15万円の投資、年150〜200万円の積立+運用
- 純資産500万→1,000万円を目標
- 副業の事業化、または資産所得の拡大を判断

## 5. 機能要件

優先度:P0(最優先)〜P5。MVPはP0+P1の一部+P2の一部。

### P0:負債の全容可視化と完済シミュレーション
- FR-01 借入先ごとに残高・金利・最低返済額・返済日・種別(リボ/カードローン/消費者金融等)を登録・編集できる
- FR-02 「最低返済のみ継続した場合」と「月X万円返済した場合」の総支払額・完済時期を並べて比較表示する
- FR-03 完済カウントダウン(残日数・残額)をホーム画面最上部に固定表示する
- FR-04 借り換えシミュレーション(金利をY%に変更した場合の短縮月数・削減利息)を提示する
- FR-05 返済実績を記録し、計画との差分を表示する

### P1:明細の自動取り込みと「使える残額」表示
- FR-10 銀行・カードの明細を取り込める(CSVインポート、およびカード利用通知メールの自動解析)
- FR-11 取引をカテゴリに自動分類する。分類カテゴリの初期値:固定費/生活費/女遊び(聖域)/浪費/投資的支出/返済/投資/収入
- FR-12 分類はAIが行い、確信度が低いもののみ本人に確認を求める。本人の修正結果を学習データとして保持する
- FR-13 カテゴリ・分類ルールは本人が自由に追加・変更・統廃合できる
- FR-14 ホーム画面に「生活費の残額」「女遊び枠の残額」を表示する(その他の詳細は下層画面に置く)
- FR-15 給料日の振替ルール(返済→投資→女遊び→生活費の順、各金額)を定義し、給料日に実行チェックリストを提示する
- FR-16 口座・カードを登録・編集できる(名称・金融機関名・種別・締め日・支払日)。取り込んだ明細はいずれかの口座に紐付く
- FR-17 給料日〜次の給料日の期間で、口座別・カテゴリ別の使用金額一覧を表示する(保存は暦月のまま、表示のみ給料日基準に変換する。ADR-015)
- FR-18 カード会社から届く「ご利用金額のお知らせ」(締め日単位の合計金額メール)を解析し、同じ締め期間に取り込んだ明細の合計と突き合わせて、差額があれば取り込み漏れとして知らせる

### P2:介入・アラート
- FR-20 浪費カテゴリが月予算の70%到達時点で通知する(100%到達では遅い)
- FR-21 明細に「リボ払い」「キャッシング」「分割払い」に該当する取引が出現した場合、即時アラートを発する(再発防止の最重要トリガー)
- FR-22 3日以上明細が取り込まれない、または本人がアプリを確認していない場合、責めないトーンでリマインドする
- FR-23 返済日の前日にリマインドする
- FR-24 通知はDiscord(またはLINE)へ送信する

### P3:毎朝配信
- FR-30 毎朝定時に以下を配信する
  1. 冒頭に必ず「完済まで残り日数 / 今月の使える残額」を記載する
  2. 収入増のヒント(本人のスキル=AI駆動開発に絞った副業・受託案件動向、スキル需要等)
  3. 市場の話題(要約のみ。個別銘柄の断定的な売買推奨は行わない)
  4. 実利のあるキャンペーン・還元施策(期限・条件・得の大きさを明記し優先度付け)
- FR-31 情報のフィルタリングルールを持つ:情報商材、根拠不明な高収入案件、詐欺性が疑われるもの、アフィリエイト目的が主のものを除外する。除外理由をログに残す
- FR-32 配信内容は保存され、後から検索・参照できる

### P4:収入増トラッカー
- FR-40 副業の作業時間と入金を記録し、時給換算を自動表示する
- FR-41 転職準備のマイルストーン(市場調査/職務経歴書/応募/面接)をチェックリスト管理する
- FR-42 副業収入の振り分け(例:返済7:投資3)を自動計算し、振替の指示を出す

### P5:投資枠管理
- FR-50 「返済額の2〜3割」ルールに基づき今月の投資額を自動算出する
- FR-51 投資残高・積立実績を記録する(証券口座連携は当面対象外、手入力またはCSV)
- FR-52 完済を検知したら「高リスク枠解禁モード」に切り替わり、配分ルール(インデックス7:高リスク3等)を変更する

### 三日坊主対策(横断要件)
- FR-60 毎朝配信を「開く理由」として機能させる
- FR-61 ホーム画面は数字3個以内に絞る
- FR-62 連続確認日数(ストリーク)を表示する。途切れても責めず「再開」だけを提示する
- FR-63 完済進捗をゲージで可視化する
- FR-64 女遊び枠は「あと〇円使える」と肯定形で表示する

## 6. 非機能要件

- NFR-01 **コスト**:ランニングコストは原則無料枠内。従量課金はAI API分のみ(月数百円以内を目安)
- NFR-02 **拡張性**:DBスキーマ・分類ルール・振替ルールを本人がSQLまたは設定画面で直接編集できる
- NFR-03 **ロックイン回避**:オープンソース基盤を優先し、将来セルフホストへ移行可能であること
- NFR-04 **セキュリティ**:本人専用。認証必須。金融明細を扱うためAPIキー・認証情報は環境変数/Secretで管理し、リポジトリに含めない
- NFR-05 **可用性**:毎朝配信の定期実行がDBへアクセスすることで、無料枠の自動停止を回避する
- NFR-06 **可観測性**:取り込み・分類・配信の各ジョブは実行ログを残し、失敗時は通知する
- NFR-07 **モバイル対応**:主な閲覧はスマートフォン。レスポンシブなWeb UIとする

## 7. データモデル(概略)

詳細設計フェーズでスキーマ化する。主要エンティティ:

- `accounts`:口座・カード(種別、名称、用途=給与/返済/投資/女遊び/生活費)
- `debts`:借入(借入先、種別、残高、金利、最低返済額、返済日、状態)
- `debt_payments`:返済実績
- `transactions`:取引明細(日付、金額、摘要、取り込み元、分類、確信度、確認状態)
- `categories`:カテゴリ(名称、種別=固定費/生活費/聖域/浪費/投資的支出等、月予算)
- `classification_rules`:分類ルール(キーワード/正規表現→カテゴリ、本人修正履歴)
- `transfer_rules`:給料日振替ルール(順序、金額、対象口座)
- `budgets`:月次予算(カテゴリ×月)
- `side_income_logs`:副業作業時間・入金
- `job_change_milestones`:転職準備チェックリスト
- `investments`:投資残高・積立実績
- `daily_briefs`:朝配信の生成結果・除外ログ
- `alerts`:発火したアラート履歴
- `job_runs`:バッチ実行ログ

## 8. システム構成(推奨)

| 層 | 選定 | 理由 |
|---|---|---|
| DB / バックエンド | Supabase(PostgreSQL, Auth, pg_cron) | スキーマで構造化できる。無料枠。オープンソースでセルフホスト可 |
| フロントエンド | Next.js または SvelteKit(Vercel / Cloudflare Pages) | 無料枠。AI駆動開発との相性が良い |
| AI処理 | Claude API(軽量モデル) | 明細分類・朝配信生成・情報フィルタ。上位モデルは設計・改修相談のみに使用 |
| 定期実行 | Supabase pg_cron または GitHub Actions(schedule) | 無料。毎朝配信・取り込み・アラート判定のトリガー |
| 通知 | Discord Webhook(またはLINE Messaging API) | 自分専用なら最も低コスト・低工数 |
| 明細取り込み | CSVインポート + Gmail API(カード通知メール解析) | 国内金融機関に個人向け無料APIがほぼないための現実解 |

Firebaseは検討の結果、NoSQLであること・定期実行に有料プランが必要なこと・ロックインの観点から採用しない。

## 9. 外部連携

- 9.1 **CSV**:各銀行・カードの明細CSVを月次で手動取り込み。フォーマット差異はアダプタで吸収する
- 9.2 **Gmail API**:カード利用通知メールを定期取得し、AIで構造化(日付・金額・店名・支払方法)して`transactions`へ登録。リボ/キャッシング検知の主経路
- 9.3 **Web検索(AI経由)**:朝配信の情報収集
- 9.4 **Discord / LINE**:通知の配信先
- 9.5 有料の口座連携APIは完済後に再検討する

---

## 10. AI利用方針

- 明細分類:確信度を返させ、閾値未満は本人確認へ回す。本人の修正はルールとして蓄積する
- 朝配信:収集→フィルタ→要約の3段階。フィルタ段階で除外理由を必ず記録する
- 禁止事項:個別銘柄の断定的な売買推奨、税務・法務の個別判断、根拠不明な高収入情報の紹介
- 上位モデル(Fable等)の用途:本書からの詳細設計・スキーマ生成、リファクタリング相談、ロードマップの定期見直し。日次処理には使用しない

## 13. リスクと対策

| リスク | 対策 |
|---|---|
| リボ・キャッシングの再発 | FR-21即時アラート + 該当カード停止を運用ルール化 |
| 負債があるうちの高リスク投資 | FR-52により完済前は高リスク枠を無効化 |
| 明細取り込みが面倒で放置 | Gmail自動解析を優先実装。CSVは月1の「整理の儀式」として位置づけ |
| 三日坊主 | 朝配信を開く理由にし、ホームを数字3個に絞る。途切れても責めない |
| 無料枠の自動停止 | 定期ジョブでDBアクセスを維持 |
| 怪しい情報の混入 | FR-31フィルタと除外ログ |
| 転職が進まない | 副業比重を上げる方針へ切替(ロードマップの見直しトリガー) |
