## P1-1: 見ている対象を、次の画面でも保つ

**現状**

「月のふりかえり」は月を切り替えられますが、「回数と1回の金額」「AIレポート」のリンクに月が付かず、遷移先は今月を読みます。頻度のリンクに添える要約も最初に読み込んだ月のままです。

通常カテゴリの行はカテゴリIDだけを共通シートへ渡し、そのシートは今日を基準に今期の目標・見込みを読みます。過去月の内訳から開く場合にも、期間が切り替わります。**未分類の行は選択月を引き継いでおり、この問題の対象外です。**

**提案**

- 月・カテゴリ・必要な絞り込み・戻る先を遷移時に引き継ぎます。
- 過去月のカテゴリ行は「その月の内訳」を開きます。「今期の目標を調整」は目的を明示した別操作として残します。
- 頻度・AIの見出しと集計も選択月にそろえます。対象月のAIレポートが無い場合は、その事実と次の操作を表示します。
- 年間グラフなど期間の異なる分析は、その対象期間を明記します。一律に月集計へ変える必要はありません。
- 戻るときも月・絞り込み・スクロール位置を復元します。現在の復元処理はフィルターとスクロールを持ちますが、表示月は初期月から始まるため、月も対象に加えます。

例: 9月のふりかえり → 9月の食費 → 同じ9月のふりかえり。

**維持する機能:** 月切替、今期の予測・目標調整、未分類処理、頻度、AI、年間分析のすべて。

**根拠:** [月表示と固定リンク](https://github.com/toshikikotani/git-study/blob/4b603ae78403021644df549b68e040704edba18e/app/(app)/reports/month/page.tsx#L28)、[頻度の対象月](https://github.com/toshikikotani/git-study/blob/4b603ae78403021644df549b68e040704edba18e/app/(app)/reports/frequency/page.tsx#L9)、[AIレポートの読み込み](https://github.com/toshikikotani/git-study/blob/4b603ae78403021644df549b68e040704edba18e/app/(app)/reports/ai/page.tsx#L24)、[通常カテゴリと未分類の分岐](https://github.com/toshikikotani/git-study/blob/4b603ae78403021644df549b68e040704edba18e/app/(app)/spending/genre-breakdown.tsx#L63)、[今期を読むカテゴリシート](https://github.com/toshikikotani/git-study/blob/4b603ae78403021644df549b68e040704edba18e/app/(app)/category-sheet-actions.ts#L28)、[表示月と状態復元](https://github.com/toshikikotani/git-study/blob/4b603ae78403021644df549b68e040704edba18e/app/(app)/spending/spending-month-provider.tsx#L106)。

## P1-2: 対象を見つけた後に、探し直させない

**現状**

今日の「入力待ち」「確認待ち」は、どちらも明細全体へ移ります。今日の記録の行本文は表示用で、編集するには「すべて」から明細で探し直す必要があります。予定の一覧にも、行からの直接編集がありません。

**提案**

- 入力待ち・確認待ちバナーは対象だけの処理一覧へ進め、1件ならその処理を直接開きます。
- 未処理は月をまたぐため、現在の月・日フィルターだけで対象を隠さない設計にします。入力待ち、カテゴリ確認、金額不一致、重複は種類を区別し、同じ買い物の複数の確認はひとまとまりに扱います。
- 今日の記録・予定は行本文から共通の編集画面を開きます。カテゴリマークからカテゴリを開く操作は残します。
- 修正後は元の画面・位置へ戻します。「すべて」から一覧を見る操作も維持します。
- 下部の読み取り状況表示とホームバナーは、同じ対象・状態を参照します。

変更前: 入力待ちのお知らせ → 明細全体 → 対象を探す → 入力。  
変更後: 入力待ちのお知らせ → 対象を入力 → 次の未処理へ。

**維持する機能:** 一覧、検索、カレンダー、フィルター、順番に直す操作、一括分類、カテゴリ表示、各種未処理の確認。

## P1-3: 保存ボタンから先に進めるようにする

**現状A: レシートの唯一の選択肢**

未来日やカテゴリ目標に対して高額な支払いでは、目標の扱いを明示的に選ぶまで保存処理が戻ります。しかし選択肢は「目標に含める」の一つだけで、通常欄と注意欄に重複しています。選択済みのような表示でも、押すまで未確認扱いです。保存ボタンの無効条件にもこの状態が含まれません。

**提案A**

注意内容と、残高・目標への影響を一か所に表示します。該当時の主ボタンを「目標に含めて保存」にし、その押下を明示確認と保存にまとめます。将来、扱いを選ぶ機能が増えた場合も、同じ場所で選べる構成にします。通常の高信頼・照合一致時の自動保存は維持します。

**現状B: 口座の前提処理**

画像入力は口座未登録時に既定口座を用意します。一方、CSV・メール貼付・請求突合は口座管理への移動を要求し、文字/音声入力は口座がないと登録処理が無言で戻ります。文字/音声は先頭口座を使うため、複数口座でも入力方法によって指定の自由度が違います。

**提案B**

全入力方式で共通の口座処理にします。1口座なら表示して続行、複数なら選択・変更可能、未登録なら入力内容を保ったままその場で作成し続行します。画像の既定口座も保存先が分かるようにします。入力方式の統合で、新たな必須確認を増やさないことが条件です。

**維持する機能:** 目標への明示確認、自動保存、差額を残す保存、複数口座、口座作成、各入力方式。

**根拠:** [保存を止める条件](https://github.com/toshikikotani/git-study/blob/4b603ae78403021644df549b68e040704edba18e/app/(app)/transactions/receipt/receipt-confirm.tsx#L197)、[重複する単一選択](https://github.com/toshikikotani/git-study/blob/4b603ae78403021644df549b68e040704edba18e/app/(app)/transactions/receipt/receipt-confirm.tsx#L553)、[保存ボタンの条件](https://github.com/toshikikotani/git-study/blob/4b603ae78403021644df549b68e040704edba18e/app/(app)/transactions/receipt/receipt-confirm.tsx#L655)、[既存の自動保存](https://github.com/toshikikotani/git-study/blob/4b603ae78403021644df549b68e040704edba18e/app/(app)/transactions/receipt/receipt-confirm.tsx#L242)、[口座がない場合の終了](https://github.com/toshikikotani/git-study/blob/4b603ae78403021644df549b68e040704edba18e/app/(app)/transactions/capture-text/capture-text-form.tsx#L116)、[画像入力の口座準備](https://github.com/toshikikotani/git-study/blob/4b603ae78403021644df549b68e040704edba18e/app/(app)/transactions/receipt/page.tsx#L63)。

## P1-4: 一度済ませた判断を、繰り返さない

**現状**

重複確認の「別の買い物なので、どちらも残す」は画面内の候補を消すだけです。再読み込み・再訪時は候補を再計算するため、同じ組が再表示され得ます。「片方を残す」側は保存されます。

**提案**

別物と確認した候補ペアを永続化し、同じ内容の組には再質問しません。片方を除外した扱いにはせず、両方の支出を残します。判断を取り消す操作を用意し、日付・金額などが変わった場合の再確認条件を決めます。

**維持する機能:** 重複検知、写真の比較、片方を残す、両方を残す、判断の見直し。

**根拠:** [保存する操作と画面内だけのdismiss](https://github.com/toshikikotani/git-study/blob/4b603ae78403021644df549b68e040704edba18e/app/(app)/transactions/duplicates/duplicate-list.tsx#L33)、[候補の再計算](https://github.com/toshikikotani/git-study/blob/4b603ae78403021644df549b68e040704edba18e/src/features/transactions/duplicates-store.ts#L91)。

## P2-1: 保存単位とキャンセルをそろえる

**現状**

目標編集では配分は上部の保存、期間は別の保存、次期予約は押下時に作成されます。カテゴリシートも目標額は完了時、固定費・ホーム表示はその場で保存されます。同じ画面のキャンセルで、どこまで戻るかを覚える必要があります。

**提案**

- 編集画面の期間・総額・配分は共通の下書きとし、一つの「保存」で確定します。
- カテゴリシート内の変更も、保存対象を一つにそろえます。即時操作を残す場合は編集領域と区別し、「変更はすぐ反映」と操作ごとに示します。
- 次期予約など独立した操作は、編集を保存してから実行する流れにします。
- 通常の記録編集は共通の編集部品を基本にし、カテゴリ別の編集でも保存・取消・移動の規則をそろえます。既存の一括移動やUndoは残します。

**維持する機能:** 期間変更、自動配分、AI提案、次期予約、カテゴリ設定、固定費、ホーム表示、個別・一括編集。

**根拠:** [配分の保存](https://github.com/toshikikotani/git-study/blob/4b603ae78403021644df549b68e040704edba18e/app/(app)/plan/edit/goal-editor.tsx#L143)、[期間の独立保存](https://github.com/toshikikotani/git-study/blob/4b603ae78403021644df549b68e040704edba18e/app/(app)/plan/edit-plan-section.tsx#L24)、[次期予約](https://github.com/toshikikotani/git-study/blob/4b603ae78403021644df549b68e040704edba18e/app/(app)/plan/edit/goal-editor.tsx#L477)、[目標額の保存](https://github.com/toshikikotani/git-study/blob/4b603ae78403021644df549b68e040704edba18e/app/(app)/category-sheet.tsx#L81)、[設定の即時保存](https://github.com/toshikikotani/git-study/blob/4b603ae78403021644df549b68e040704edba18e/app/(app)/category-sheet.tsx#L231)、[共通の記録編集](https://github.com/toshikikotani/git-study/blob/4b603ae78403021644df549b68e040704edba18e/app/(app)/transactions/split-editor.tsx#L1139)。

## P2-2: 通常の操作に必要な情報を先に出す

- **CSV:** 現在は一つのページに口座・ファイル・列対応・確認が並びます。既存の列推測・前回設定を活用し、正常時は「ファイルを選ぶ → 確認して保存」を主動線にします。文字コード・列対応は要約を表示し、変更や失敗時に展開します。4画面を減らす提案ではありません。
- **レシート:** 店名・日付・支払額・要確認件数を先頭へ。修正が必要な項目に直接移動し、税・値引き・ポイント・割り勘・品目分類などは内訳からすべて操作できます。
- **目標の作成:** 期間・提案・保存を主動線とし、カレンダー・改善の強さ・根拠・細かい配分は「調整する」から開きます。
- **口座:** 種別に応じた項目を表示します。カードの締め日・支払日はカード選択時に出し、他の設定も詳細から到達可能にします。

詳細を収納しても、異常・未設定・保存への影響がある情報は最初から表示することが条件です。明細の各記録は一覧で見られる現行仕様を維持し、勝手な省略は行いません。

## P2-3: 機能は全部残し、目的に近い場所へ入口を置く

現行の「…」には通常20、オーナー24のリンクが5群に並びます。入口の説明は「設定」、開いた見出しは「その他の機能」で、機能を探すための場所が分かりにくくなっています。

4タブは維持し、以下のように近道を整理します。全機能を一覧できる索引も残します。すべてを折りたたんで操作段数だけを増やす整理は避けます。

| 入口 | 到達できる機能 |
|---|---|
| ＋ 記録する | カメラ、写真・スクショ、手入力、文字・音声、CSV、メール貼付 |
| 今日 | 今日の状況、試算、貯金、今後の支払い、今日の記録、給料日の案内 |
| 明細 | 明細・検索・カレンダー・全フィルター、入力待ち、分類/差額確認、請求突合、重複確認、口座管理 |
| 分析 | 今期の目標と編集・予約、月のふりかえり、頻度、月ごとの表、カテゴリ分析、AIレポート、固定費候補、お店、資産、予測検証などの詳細 |

| メニューの設定欄 | 初回設定の再実行、カテゴリ管理、色、AI、パスワード、Gmail、Google、読み取れなかったメール、朝配信、ログアウト |

オーナー限定の出し分けは維持します。メニューの名称を統一し、設定の戻る先も設定一覧または遷移元へそろえます。共通AIへの入口は「貯金目標の相談」などの目的を引き継ぎ、説明の繰り返しを減らします。既存の変更提案の確認・反映手順は維持します。

**根拠:** [メニューの全項目](https://github.com/toshikikotani/git-study/blob/4b603ae78403021644df549b68e040704edba18e/src/components/ui/more-menu.tsx#L10)、[入口と見出しの名称](https://github.com/toshikikotani/git-study/blob/4b603ae78403021644df549b68e040704edba18e/src/components/ui/more-menu.tsx#L128)、[貯金からの相談入口](https://github.com/toshikikotani/git-study/blob/4b603ae78403021644df549b68e040704edba18e/app/(app)/savings/page.tsx#L97)、[共通AIの初期候補](https://github.com/toshikikotani/git-study/blob/4b603ae78403021644df549b68e040704edba18e/app/(app)/assistant/assistant-chat.tsx#L38)。

## P2-4: 任意項目を入力しなくても、そのまま始められるようにする

初回設定の3段目は「貯金目標（任意）」ですが、主ボタンは貯金目標を作成する経路なので、空欄だとエラーになります。別の小さい操作で省略する必要があります。また、全体スキップは途中までの入力を保存しません。

「手取り・給料日 → 今日からの目標 → この内容ではじめる」を主動線にします。貯金目標は確認画面から任意に追加できるようにし、空なら作成せず完了します。「ここまで保存」と「入力を破棄してあとで」は動作と文言を分けます。途中の下書きを保てれば再入力も減ります。

**維持する機能:** 手取り、給料日、期間プリセット、カテゴリと金額の調整、貯金の目的・金額・期限、全設定の後回し、後日の再設定。

**根拠:** [任意項目の空欄エラー](https://github.com/toshikikotani/git-study/blob/4b603ae78403021644df549b68e040704edba18e/app/(app)/welcome/welcome-flow.tsx#L99)、[主ボタンと省略操作](https://github.com/toshikikotani/git-study/blob/4b603ae78403021644df549b68e040704edba18e/app/(app)/welcome/welcome-flow.tsx#L312)、[入力を保存しないスキップ](https://github.com/toshikikotani/git-study/blob/4b603ae78403021644df549b68e040704edba18e/app/(app)/welcome/actions.ts#L55)。

## 実施順と確認基準

**第1段階: 行き止まり・再探索・条件リセットを解消する**

P1の4項目を先行します。画面を大きく作り替えず、対象の継承・直接編集・保存前提の共通化・確認結果の保存を進めます。重複判断の永続化には保存形式の追加が必要です。金額集計や重複検出そのものを省略する変更は含めません。

**第2段階: 編集と表示の規則を統一する**

P2-1、P2-2を進めます。期間と配分の一括保存では、片方だけが保存されないよう同じ編集単位として扱います。詳細の収納には、保存に影響する情報を隠さない条件を適用します。

**第3段階: メニューと初回設定を整理する**

P2-3、P2-4を進めます。旧URLや既存の近道からも同じ機能に到達できるようにし、機能の孤立を防ぎます。

| 確認する場面 | 合格条件 |
|---|---|
| 過去月から頻度・AI・通常カテゴリを開く | 対象月が一致し、戻っても月と位置が保たれる。今期調整は別の目的として明示される |
| 入力待ち・カテゴリ確認待ち | 月や日を選び直さず対象の処理を始められる |
| 今日・予定の行を編集する | 一覧で探し直さず開き、保存後に元の位置へ戻れる |
| 未来日・高額のレシート | 主ボタンだけで意図の明示と保存が成立し、無反応にならない |
| 口座が0/1/複数 | 全入力方式で保存先を把握でき、未登録でも入力内容を失わず進める |
| 別物と確認した重複候補 | 再読み込み・再訪しても同じ内容では再質問しない。判断を見直せる |
| 目標・カテゴリのキャンセル | 同じ編集単位の未保存変更が取り消され、即時操作がある場合は範囲が明示される |
| CSV推測失敗、画像不一致、低信頼 | 詳細・失敗行・照合情報を開いて修正できる。自動保存条件は維持される |
| 貯金目標を空欄にした初回設定 | 主ボタンで正常に開始できる |
| 全機能への到達 | 上の対応表と既存リンクを照合し、通常/オーナー双方で削除や孤立がない |

改善前後では、同じ条件のタスクで「完了までの操作数」「対象の再探索」「再入力」「戻る操作」「同じ確認の再提示」を比較します。まず再探索と無反応をゼロにすることを評価軸にし、利用頻度を測ってから表示順を調整します。
