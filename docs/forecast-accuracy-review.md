# 確率分布と校正の確認（2026-10-18）

実機では「18.9万円以内が1%未満」と「15.5万円以下が3%」が同時に表示された。同じ分布では
金額が低いほうの累積確率が高くなることはない。目標内の確率は試行とPIT補正、分布の形と操作は
別の正規近似を使っていた。今回、表示・タップ・予測区間を同じ試行にそろえる。

目標の補正も対象カテゴリと特別費の扱いをそろえ、全体用の合成母集団補正を限定した目標へ流用しない。
補正に使った同じ月での的中率は「過去の記録での確認」と表示し、将来の精度とは区別する。

## 全体の変更前後（合成データ96予測）

既存の決定論的な評価を変更前と変更後に同じ条件で実行する。合成世帯0の記録の長さが違う4条件を使い、
各月の2日目・12日目・22日目、合計96予測を測る。校正は各月の初日に記録済みの完了月だけ、
予測はその時点までに記録済みの明細だけを使う。注意の評価は省略する。

```bash
# 変更前に保存
EVAL_STEP=10 H=1 EVAL_CAUTIONS=0 EVAL_QUICK_DIR=/tmp/forecast-accuracy node --import tsx scripts/forecast-eval/quick.ts --save before
# 変更後に同じ保存先と比較
EVAL_STEP=10 H=1 EVAL_CAUTIONS=0 EVAL_QUICK_DIR=/tmp/forecast-accuracy node --import tsx scripts/forecast-eval/quick.ts --save after --compare before
```

| 指標 | 変更前 | 変更後 |
|---|---:|---:|
| 予測数 | 96 | 96 |
| 80%区間の的中率 | 76.0% | 76.0% |
| 中央値の偏り Σ(実際−中央)÷Σ実際 | +0.1% | +0.1% |
| CRPS（円、小さいほど良い） | 16,242 | 16,242 |

この集合では変更前後の指標は一致した。全体の予測精度が改善したとする結果ではなく、
表示の矛盾と範囲外の校正の流用を直しても、既存の全体評価を悪化させなかったことを確認する。

## 目標の範囲をそろえた補正（合成データ12予測）

再現用スクリプトは `scripts/forecast-eval/scoped.ts`。合成世帯0の2026年7月・8月、外食・食料品、
各月2日目・12日目・22日目の **2か月 × 2カテゴリ × 3時点 = 12予測** を使う。
それぞれの対象カテゴリだけ、明示的な特別費を除く目標として測る。

同じ現在のエンジン・明細・試行数2,000・乱数の種で、以下を比べる。各月の校正に対象月の結果を使わない。

- 全体の補正を流用し、全体用の合成母集団補正も使う。
- 目標と同じ範囲で補正し、全体用の合成母集団補正を使わない。

```bash
EVAL_SCOPE_OUT=/tmp/forecast-scoped.json node --import tsx scripts/forecast-eval/scoped.ts
```

生の12予測と両方の結果を指定したJSONへ書き、全体・カテゴリごとの指標を標準出力に出す。
出力先を指定しないときはOSの一時ディレクトリを使い、リポジトリ内には結果を書かない。

| 指標 | 全体の補正を流用 | 範囲をそろえる |
|---|---:|---:|
| 予測数 | 12 | 12 |
| CRPS（円） | 3,262 | 2,452 |
| 中央値の平均絶対誤差（円） | 4,625 | 3,233 |
| 80%区間の的中率 | 83.3%（10/12） | 91.7%（11/12） |
| 外食のCRPS（6予測、円） | 3,972 | 2,402 |
| 食料品のCRPS（6予測、円） | 2,552 | 2,502 |

この12予測でCRPSは約24.8%小さくなった。的中率は80%に近いことが目安で、単に高ければよい指標ではない。
CRPSは着地分位5〜95%の19点による既存の近似値で、中央値の平均絶対誤差とともに円単位。

## この結果で分からないこと

- 本人の本番明細を取得して再評価した結果ではない。一般の利用者や本人の精度が24.8%改善したとは言えない。
- 12予測は同じ世帯・同じ月の別時点を含む小標本で、独立した12世帯の評価ではない。
- 範囲の比較は校正と母集団補正の扱いを同時に変えている。どちら単独の効果かは分けて測っていない。
- 既存の合成データに曜日・季節・入力遅延などを入れているが、実際の生活の全ての変化を再現してはいない。
- 暦月で評価しており、実機の10月1日〜11月5日など任意長期間での的中率は未確認。
- 以前からあるバックテストの中心補正は残り全体で推定し、本番では月払い請求を中心補正の対象外とする。
  この差は今回変更していない。合成評価と画面上の過去月確認を、将来精度の保証には使わない。
