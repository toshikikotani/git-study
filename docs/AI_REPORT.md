# AIレポートの仕組み(現在の実装)

画面は `/reports/ai`(レポート画面の「AIに見てもらう」)。コードは `src/features/ai-report/`、
プロンプトは `src/prompts/`、AI の呼び出しの共通部分は `src/lib/ai-gateway/`。決めた理由は ADR-031・ADR-032。

## 全体の流れ

```
本人がボタンを押す
  → 入力の数字を集計(AIには計算させない)
  → 数字を文章にして AI に渡す
  → AI は決まった形(JSON)で文章だけを返す
  → 返ってきた文章の数字を、渡した数字と突き合わせる
  → 合っていれば保存して表示(1か月1件・1日1件。作り直すと上書き)
```

- AI を呼ぶのは、本人がボタンを押したときだけ(画面を開いただけでは呼ばない)。
- 数字(合計・比率・平均・着地の見込み)はすべて家計簿・診断・ホーム・確率予測と同じ集計関数で出す。
  AI は文章を書くことと、決まった選択肢から「AIの読み」の補正を選ぶことだけをする。
- モデルは `claude-sonnet-5-5`(月次・日次とも)。

## 1. 月次レポート(`monthly-report-ai.ts`)

### 入力(今月の数字)

| 項目 | 出どころ | 中身 |
|---|---|---|
| 総支出・総収入 | 家計簿の月の集計(`loadMonthlyLedger`) | 家計簿の見出しと同じ |
| 浪費・必要経費の額 | 支出の診断(`loadSpendingDiagnosisView`) | AI 診断で「浪費」「必要」とされた明細の合計 |
| 浪費比率 | 同上 | `浪費 ÷ (浪費 + 必要経費)`。診断が無ければ「まだ無い」 |
| 未診断の件数 | 同上 | 今月まだ診断していない支出の件数 |
| カテゴリ別支出 | 家計簿のジャンル別内訳 | 支出のあるジャンルを多い順に最大 10 件。予算があれば添える |
| 浪費・必要経費の明細 | 診断の結果 | それぞれ金額の大きい順に最大 10 件(店名・金額・診断の理由) |
| 浪費比率の推移 | 診断の月ごとの集計 | 診断のある月だけ |
| 返済の状況 | ホームの完済の見込み(`loadHomeSummary`) | 残債・進捗率・今月の返済額・完済までの日数 |
| 着地の見込み | 確率予測 v2(`loadForecast`、`docs/FORECAST_MODEL.md`) | 中央・下振れ〜上振れ、決まっている額、未記録・請求・来店・特別費の見込み、残りの1日あたり、直近14日の1日あたり、ジャンル別の着地(最大10件)、「目安」かどうか |
| 目立つ明細 | 今月の明細と、レシートの品目 | 金額の大きい8件と、メモのある8件(日付・店名・金額・ジャンル・メモ・品目名6つまで) |
| これからの予定 | 今月の、今日より先の日付の明細 | 最大10件(日付・店名・金額・ジャンル) |
| 残りの日の暦 | `domain/forecast/calendar.ts` | 休みの日数、平日の祝日の日数、3日以上の連休、給料日(土日祝なら前の平日)、年末年始・GW・お盆・年度替わり |
| 過去のAIの読み | `ai_forecast_reads` と各月の実際の着地 | 直近6か月、月ごとに最初の読み。補正・統計・AIの読み・実際と、どちらが近かったか |

AI に渡す本文は、上の表をそのまま箇条書きにしたもの(金額は円の整数、比率は % に丸める)。

### 出力(AI が返す形)

| 項目 | 決まり |
|---|---|
| `personaType` | 支出の傾向のタイプ。決まった 6 つから 1 つだけ選ぶ(下の表)。新しい分類は作らせない |
| `personaReasoning` | 1〜2 文。そのタイプにした理由を、渡した数字を根拠に |
| `insights` | 気づき 3〜5 件。渡した数字を具体的に引用する |
| `advice` | アドバイス 3〜5 件。支出の行動(買い物のタイミング・記録の習慣・予算の見直しなど)の一般的な工夫だけ |
| `forecastRead.percent` | AIの読み。統計の「残りの支出」を何%動かすか。−20・−10・−5・0・+5・+10・+20・+30 から1つ |
| `forecastRead.reason` | 1〜2 文。統計が見ていない事情を、渡した事実だけで説明する |
| `forecastRead.evidence` | 根拠にした事実 1〜3 件(渡した表記のまま) |

| タイプ | 画面の名前 | 説明 |
|---|---|---|
| impulsive | 衝動買い型 | 計画外の突発的な支出が多い傾向 |
| steady | 堅実型 | 支出が安定していて予算内に収まりやすい傾向 |
| social | 交際費型 | 人との付き合いに使う支出が多い傾向 |
| goal_oriented | 目標志向型 | 貯蓄・投資・返済など明確な目的に向けて支出を絞れている傾向 |
| frugal | 倹約家型 | 全体的に支出を抑える傾向が強い |
| balanced | メリハリ型 | 使うところと締めるところの差がはっきりしている傾向 |

タイプは支出の「傾向」の説明で、性格や体質の断定ではない。

### AIの読み(ADR-072)

統計の見込み(確率予測 v2)は、過去の記録の曜日・給料日・季節・今月の水準から出す。統計が知らない事情
(明細のメモ・品目に出た予定や出来事、予定の中身、残りの日の連休や時期)があるときだけ、AIが補正を選ぶ。
事情が無ければ 0。予定の金額そのものは統計に入っているので、付随して増えそうな支出だけを考えさせる。

金額はアプリが計算する:

```
当たり具合 w = (AIの読みが統計より実際に近かった月 + 1) ÷ (比べた月 + 2)      記録が無ければ 0.5
AIの読み = 決まっている額 + (統計の値 − 決まっている額) × (1 + 補正% × w ÷ 100)
```

- 比べるのは、過去 6 か月の月ごとに最初の読み(月の初めほど当てるのが難しく、役に立つため)。補正 0 の月は数えない。
- 下振れ・中央・上振れのそれぞれに同じ式を当てる。
- 読みは、レポートを作るたびに `ai_forecast_reads` に1行足す(上書きしない)。

画面には、統計(中央・下振れ〜上振れ)と AIの読み(中央、補正と効かせた割合)を並べ、理由・根拠と、
これまでの当たり具合(◯回中◯回)を出す。レポート画面(`/reports`)の見出しの下にも、今月の全体の見込みのときは
最新の AIの読みを日付つきで出す。統計の数字は置き換えない。

## 2. 日次レポート(`daily-report-ai.ts`)

### 入力(今日の数字)

| 項目 | 中身 |
|---|---|
| 今日の支出と件数 | 今月の明細のうち、今日の日付の支出の合計と件数 |
| 今日のカテゴリ別支出 | 今日の支出をジャンルごとに多い順(ジャンルが無ければ「未分類」) |
| 今月の 1 日あたり平均 | `今月ここまでの支出 ÷ 今月の経過日数`(円に四捨五入)。比べる基準 |
| 今日の浪費・必要経費の明細 | 診断の結果のうち今日の日付のもの(店名・金額・理由) |
| 今月の着地の見込み | 確率予測 v2 の中央・下振れ〜上振れと、残りの1日あたりの見込み(作れなければ渡さない) |

### 出力

| 項目 | 決まり |
|---|---|
| `insights` | 気づき 2〜4 件。今日の数字を具体的に引用する。今日の支出が無ければ、事実だけを書く |
| `advice` | アドバイス 2〜4 件。明日以降の支出の行動の一般的な工夫だけ |

- 日次ではタイプ判定をしない。1 日分では、その日の偏りで判定がぶれるため(月次に一本化)。

## 3. AI に守らせること(プロンプト、`src/prompts/`)

月次・日次とも共通:

- 渡した数字だけを根拠にする。渡していない情報(食事・睡眠・ホルモン・血液検査・生年月日から推測する性格など)を作らない。
- 医学的な診断、体質の断定、食事・サプリ・栄養の助言は一切書かない(本人の指定)。
- アドバイスは支出の行動に関する一般的な工夫に限る。
- 気づきは数字(円・%・件数)を引用する。「使いすぎ」のような曖昧な言い方だけで終わらせない。

月次だけ:

- AIの読みは、統計が知らない事情があるときだけ動かす。弱ければ 0。
- 予定の金額は統計に入っているので、付随する支出だけを考える。
- 過去の読みが統計より外れていたなら、同じ向きの補正を控えめにする。
- 理由と根拠に、自分で計算した金額を書かない。

日次だけ:今月の着地の見込みがあれば、今日の支出を「残りの1日あたりの見込み」と比べてよい。

プロンプトには版番号が付いている(月次・日次とも版 2)。

## 4. 出力の確かめ方(`src/lib/ai-gateway/`)

**形の検証**: 返答は決まった形(JSON のスキーマ)で受け取る。形が崩れていたら 1 回だけ自動でやり直す。
それでも駄目ならエラーとして出す。

**数字の突き合わせ**(AI に計算させないための仕組み)

```
渡した本文に出てくる数字を全部抜き出す(= 事実)
返答の文章(理由・気づき・アドバイス・AIの読みの理由と根拠)に出てくる数字を全部抜き出す
13 以上の数字が、事実のどれかと ±0.5 以内で一致するか
  1 つでも一致しなければ → そのレポートは捨てて「台帳と一致しない数字があったため、今回は表示しません」
```

- 桁区切りのカンマは数字の一部として読む(12,000 → 12000)。
- 13 未満の数字(「2倍」「3件」など)は無条件に通す。言い回しで新しく出てくる小さな数を弾かないため。
- つまり、AI が自分で計算した金額(差額・合計など)が本文に無ければ、そのレポートは出ない。

**中身の検証**: 理由・気づき・アドバイスの空の項目は捨てる。どれかが空になったら「返答が不十分」として出さない。
多すぎるときは、月次は 5 件、日次は 4 件で切る。

## 5. オン/オフ・キャッシュ・保存

- **AI の一括オフ**: 設定の `ai_enabled` が off なら AI を呼ばず、「AI機能はオフになっています(設定でオンにできます)。」と出す。
- **API キー**: サーバーだけで使う。キーが無ければ「AI によるレポート生成」が使えない旨を出す。
- **キャッシュ**: 同じ入力(数字が 1 つも変わっていない)なら、24 時間は前回の結果を使う(DB の `ai_cache`、
  キーは「機能名 + 入力のハッシュ」)。失敗した結果はキャッシュしない。
- **保存**: 月次は `ai_monthly_reports`(1 か月 1 件)、日次は `ai_daily_reports`(1 日 1 件)。作り直すと上書き。
  テーブルが無いときは「レポート機能はまだ利用できません」。AIの読みは `ai_forecast_reads`(作るたびに1行)。
  このテーブルが本番に無い間は保存を飛ばし、過去の読みは無いものとして扱う(補正は半分だけ効く)。

## 6. 画面

- 上から、日次レポート・月次レポート・ジャンル別の内訳(家計簿と同じ集計・同じ部品)。
- 月次はタイプ(名前と説明)・理由・気づき・アドバイス。日次は気づき・アドバイス。

## 今の限界

- 浪費・必要経費の数字は、明細ごとの AI 診断が済んでいる分だけ。未診断が多い月は、浪費比率が実態とずれる
  (未診断の件数は AI に渡しているので、文章でそれに触れることはできる)。
- AIの読みの当たり具合は、月が終わってから数える。使い始めの数か月は、補正は半分だけ効く。
- AIの読みは月全体に1つの%。ジャンルごとの補正はしない。
- 明細のメモと品目名を AI に渡す(本人が選んだ根拠)。
- AI が計算した派生の数字(差額・何倍など 13 以上のもの)は、本文に無いと弾かれる。弾かれたときは、
  もう一度作り直すと別の言い回しで通ることがある。
