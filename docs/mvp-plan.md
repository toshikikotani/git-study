# MVP 実装計画

要求仕様書 v0.1 11章「MVPスコープ(最初の2〜3週間)」を、**1セッションで完了できる粒度** に分割したもの。

- 1タスク = 1セッション = 1コミット(または1PR)
- 各タスクは「これだけで動作確認できる」単位にする。画面のない機能、機能のない画面を作らない
- 依存を持たないタスクは並行して進めてよい。依存関係は各タスクの「依存」欄を見る

## 共通の完了条件(全タスクに適用)

すべてのタスクは、以下を満たして初めて完了とする。

1. `npm run lint` / `npm run typecheck` / `npm run test` が通る
2. スキーマを変更した場合、`./scripts/verify-schema.sh` が通り、`docs/schema.sql` と `supabase/migrations/` の両方が更新されている
3. 金額計算を含む場合、境界値(残高0・金利0・返済額が利息未満・月をまたぐ)の単体テストがある
4. 画面を追加した場合、スマートフォン幅(375px)で崩れない(NFR-07)
5. `TASKS.md` の該当行が Done に移り、実装中に見つかった新しいタスクが Backlog に追記されている

## スコープ

| # | 仕様書 11章の項目 | 対応タスク |
|---|---|---|
| 1 | `debts` + 完済シミュレーション(FR-01〜04) | M1-1 〜 M1-6 |
| 2 | `transactions` + CSV取り込み + AI分類(FR-10〜13) | M2-1 〜 M2-6 |
| 3 | リボ・キャッシング検知 → Discord(FR-21, FR-24) | M3-1 〜 M3-3 |
| 4 | 給料日振替ルール + 使える残額(FR-14, FR-15) | M4-1 〜 M4-4 |
| 5 | 朝配信の最小版(FR-30の一部) | M5-1 〜 M5-3 |

**MVP 対象外**(仕様書 11章):副業トラッカー(P4)、投資枠管理(P5)、ストリーク(FR-62)、Gmail連携(フェーズ2)。スキーマには席を用意してあるが、画面もジョブも作らない。

## S1:負債と完済シミュレーション(6タスク) — FR-01〜05

MVP の中核。**ここが動けば本システムは最低限の価値を持つ。**

### M1-1 完済シミュレーションのロジック
- **目的**:数字の正しさを最初に固める
- **成果物**:`src/domain/payoff.ts`(単一債務・複数債務・アバランチ/スノーボール/最低返済のみ)。単体テスト。**SQL 関数 `simulate_total_payoff()` と同一入力で結果が一致することのテスト**
- **DoD**:境界値(残高0、金利0、返済額 < 利息 でエラー、1円残り)を含むテストが通る。SQL と TS の突き合わせテストが通る
- **依存**:M0-1, M0-2
- **サイズ**:M
- **注意**:これは二重実装であり意図的なもの(`docs/architecture.md` §3.1)。突き合わせテストを省くと数字が二種類存在することになる

### M1-2 債務の登録・編集画面
- **目的**:負債の全容を入力できるようにする(FR-01)
- **成果物**:`/debts` 一覧、追加・編集フォーム(借入先・種別・残高・金利・最低返済額・返済日)。`is_estimated` の「推定値」バッジと「正確な値を入力する」導線
- **DoD**:ADR-006 の仮置き3件が表示される。金利を `15` と入力すると「15% は 0.15 として保存されます」と明示されるか、パーセント入力欄として扱われる(DB には小数で入る)
- **依存**:M0-3, M0-5
- **サイズ**:M

### M1-3 完済シミュレーション画面
- **目的**:「最低返済のみ」と「月X万円」を並べて見せる(FR-02)
- **成果物**:`/debts` 内のシミュレーション区画。月額返済額のスライダー(Client Component、即時再計算)。総支払額・完済時期・総利息の比較表。返済戦略の切り替え(アバランチ/スノーボール)
- **DoD**:スライダーを動かすと往復なしで数字が変わる。最低返済のみとの差額(削減できる利息・短縮できる月数)が表示される
- **依存**:M1-1, M1-2
- **サイズ**:M

### M1-4 借り換えシミュレーション
- **目的**:おまとめの判断材料を出す(FR-04)
- **成果物**:金利を Y% に置き換えた場合の短縮月数・削減利息の表示。`repayment_scenarios` への保存・呼び出し
- **DoD**:年8%に置き換えると削減利息が表示される。保存したシナリオが再訪時に復元される
- **依存**:M1-3
- **サイズ**:S

### M1-5 ホームの完済カウントダウン
- **目的**:最上部に固定表示する(FR-03, FR-61)
- **成果物**:ホーム最上部の「完済まで残り◯日 / 残り◯円」。進捗ゲージ(FR-63)。`is_estimated` が残る間は「推定」注記
- **DoD**:スマートフォンでスクロールせずに見える。推定値が1件でもあれば注記が出る
- **依存**:M1-1, M1-3
- **サイズ**:S

### M1-6 返済実績の記録と計画差分
- **目的**:計画どおり進んでいるかを見せる(FR-05)
- **成果物**:`debt_payments` の登録フォーム。計画 vs 実績の差分表示。返済後の残高自動更新
- **DoD**:返済を1件登録すると `debts.current_balance_yen` が減り、カウントダウンが更新される。残高0で `status='paid_off'` に遷移する
- **依存**:M1-2
- **サイズ**:M

## S2:明細の取り込みと分類(6タスク) — FR-10〜13

### M2-1 CSV パーサとアダプタ
- **目的**:どのフォーマットでも取り込めるようにする(ADR-007)
- **成果物**:`src/features/import/csv.ts` と `adapters.ts`。文字コード自動判定(Shift_JIS 対応)、複数の日付形式、出金/入金の2列形式、桁区切り・全角数字の正規化。匿名化した fixture でのゴールデンテスト
- **DoD**:Shift_JIS の CSV と UTF-8 の CSV の両方が同じ結果になるテストが通る。`2026/09/08` `20260908` `2026-09-08` がすべてパースされる
- **依存**:M0-1
- **サイズ**:L
- **注意**:MVP で一番地味に重い。文字コードと日付形式で必ず躓く

### M2-2 取り込み画面
- **目的**:月1の「整理の儀式」を成立させる(13章)
- **成果物**:`/import`。ファイル選択 → プレビュー → 列マッピング指定 → 確定。`import_adapters` へのマッピング保存。`import_batches` の作成と結果表示(取込 / 重複 / 失敗の件数)
- **DoD**:同じファイルを二度取り込むと「重複のため中断」と表示され、明細が増えない。マッピングを保存すると次回は指定不要
- **依存**:M2-1, M0-3
- **サイズ**:L

### M2-3 ルールベース分類
- **目的**:AI を呼ばずに済む分を先に処理する(ADR-010)
- **成果物**:`src/features/classification/rules.ts`。`classification_rules` を priority 昇順で適用。keyword / regex / exact / amount_range / merchant の各方式。`hit_count` の更新
- **DoD**:シードの検知ルール3件が正しく `payment_method` を設定する。ルールが無い明細は `unclassified` のまま残る
- **依存**:M0-2
- **サイズ**:M

### M2-4 AI 分類
- **目的**:残りを自動分類する(FR-11, FR-12)
- **成果物**:`src/features/classification/ai.ts`。Claude Haiku 4.5 へ20〜50件をバッチ送信。カテゴリ + 確信度を受け取る。閾値未満は `review_status='pending'`。トークン数と件数を `job_runs.detail` に記録
- **DoD**:100件の明細が3リクエスト以内で分類される。確信度なしのレスポンスは DB 制約で弾かれる(`ck_transactions_ai_needs_confidence`)
- **依存**:M2-3
- **サイズ**:M

### M2-5 確認待ちキューと学習
- **目的**:本人の修正をルールとして蓄積する(FR-12)
- **成果物**:`/transactions/review`。確認待ち明細の一覧、1タップでカテゴリ修正。修正時に `classification_rules`(`is_learned=true`)を自動生成
- **DoD**:1件修正すると学習ルールが1件増え、同じ摘要の次の明細は AI を経由せず分類される
- **依存**:M2-4
- **サイズ**:M

### M2-6 カテゴリ・ルール編集画面
- **目的**:本人がスキーマを整えられるようにする(FR-13, NFR-02, 設計原則1)
- **成果物**:`/rules`。カテゴリの追加・改名・統廃合(`merged_into_id`)、月次予算の設定。分類ルールの一覧・優先度変更・有効無効・削除。ルールごとのヒット数表示
- **DoD**:カテゴリを統合すると、旧カテゴリの明細が新カテゴリで集計される。ルールの優先度を入れ替えると分類結果が変わる
- **依存**:M2-5
- **サイズ**:M

## S6:口座管理と請求突合(4タスク) — FR-16〜18

MVP後、実運用で「取り込み漏れに自分では気づけない」という要望から追加。
ADR-015 が想定していた「保存は暦月、表示は給料日基準」を実際に作る。

### M6-1 口座(カード)の登録・編集画面

- **成果物**:`/accounts`。`accounts` の一覧・登録・編集(名称・金融機関名・種別・締め日・支払日)

- **サイズ**:S

### M6-2 取り込み時に口座を選べるようにする
- **目的**:明細をどの口座の分か紐付ける(FR-16)。現状 `accountId` が `'pending'` 固定で機能していない欠落を解消
- **成果物**:CSV取り込み・貼り付け画面で対象口座を選択してから取り込む。`transactions.account_id` に反映
- **DoD**:口座Aを選んで取り込んだ明細が、一覧で口座Aのものとして区別できる

### M6-3 給料日〜給料日の期間ビュー

- **依存**:M6-2
- **サイズ**:M

### M6-4 請求金額メールとの突合
- **目的**:取り込み漏れを本人が気づく前にシステムが検知する(FR-18)

- **DoD**:合計金額メールを貼り付けると、取り込み済み明細の合計と比較した差額が表示される。一致していれば「一致」と分かる表示になる

## S7:投資(3タスク) — FR-50〜52

`investment_contributions` / `investment_snapshots` はスキーマに存在(M0-2 で適用済み)。
`app_settings.investment_ratio_of_repayment` / `is_high_risk_unlocked` / `high_risk_allocation_ratio`
も同様。ここではこれらを使う計算・画面を作る。

### M7-1 投資額の自動算出ロジック
- **目的**:「今月いくら投資に回すか」を毎回考えなくて済むようにする(FR-50)
- **成果物**:`src/domain/investment.ts` の `computeInvestmentPlan()`。返済目標額 ×
  `investment_ratio_of_repayment` を投資総額とし、`is_high_risk_unlocked` が立っていれば
  `high_risk_allocation_ratio` でインデックス枠・高リスク枠に分ける(完済前は全額インデックス枠)
- **DoD**:返済目標10万円・比率20%なら投資総額2万円。高リスク枠解禁前は2万円全額がインデックス枠に入る
- **依存**:M0-2
- **サイズ**:S

### M7-2 投資記録画面
- **目的**:拠出(フロー)と残高(ストック)を記録する(FR-51)。証券口座連携は当面対象外
- **成果物**:`/investments`。`investment_contributions`(いつ・いくら・どの商品・高リスク枠か)と
  `investment_snapshots`(時点残高)の手入力・一覧。M7-1 の「今月の投資目安」もここに表示
- **DoD**:1件記録すると一覧に出る。残高スナップショットは同じ日・同じ商品なら上書きされる
- **依存**:M7-1
- **サイズ**:M

### M7-3 完済検知による高リスク枠解禁
- **目的**:完済という節目に配分ルールを自動で切り替える(FR-52)
- **成果物**:全負債の残高が0になったことを検知し `app_settings.is_high_risk_unlocked` を立てる処理。
  ホームまたは投資画面に「高リスク枠が解禁されました」の通知
- **DoD**:全負債を完済すると、次回アクセス時に投資画面の配分がインデックス7:高リスク3に変わる
- **依存**:M7-1, M1-2
- **サイズ**:S

### 優先順位

同時に着手できるタスクが複数ある場合は、この順で選ぶ。

1. **S1(負債)** — 目的1「負債を約1年で完済」に直結する。ここが動かなければ他は無意味
2. **S3(リボ検知)** — 再発防止。負債が増えると全計画が崩れるため、予防が復旧より安い
3. **S4(残額)** — 日々開く理由になる。三日坊主対策(FR-60〜64)
4. **S2(取り込み)** — S4 の精度を上げる。手入力でも当面は動くため急がない
5. **S5(朝配信)** — 継続の仕掛け。他が動いていないと配信する中身が無い
